# DNU project guidance

Before changing story collection, selection, placement or story text, read [the editorial policy](public/editorial-policy.md). Before changing the interface, visual design or exports, read [the site specification](public/site-specification.md). Both are available by direct URL under `/dnu/`, without links on the main public site. Treat the latest direct user instruction as superseding a conflicting item, then update the relevant document and implementation together.

These documents describe intended behavior. Verify the current code and prepared edition before claiming that a rule is enforced or that a source was checked. Never put API keys or passwords into either document or the repository.

## NEWSRUN shortcut

When the user sends `NEWSRUN` as an instruction (case-insensitive), prepare and publish a complete DNU edition. Use the last 24 hours ending at the time of the run in Europe/Vienna unless the user states another coverage window. Follow the editorial policy and the latest user instructions. Check every configured source, using feeds and headline listings first, then Firecrawl for promising original article pages; investigate zero-result sources with alternate permitted routes. Reuse the article cache, verify publication dates on article pages, review relevance, summaries, placement, duplicates and source diversity, and keep a source-level audit. Update the prepared edition, run the relevant checks and build, then publish the website. Once the shared Supabase project is active, also run `npm run publish:shared` with server-only Supabase credentials so public visitors see the new edition. Report the coverage window, article and source counts, unresolved sources and any collection or publication blocker. Do not claim a complete run when one did not occur. Merely discussing or defining `NEWSRUN` does not trigger a scrape.
