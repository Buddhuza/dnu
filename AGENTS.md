# DNU project guidance

Before changing story collection, selection, placement or story text, read [the editorial policy](public/editorial-policy.md). Before changing the interface, visual design or exports, read [the site specification](public/site-specification.md). Both are available by direct URL under `/dnu/`, without links on the main public site. Treat the latest direct user instruction as superseding a conflicting item, then update the relevant document and implementation together.

These documents describe intended behavior. Verify the current code and prepared edition before claiming that a rule is enforced or that a source was checked. Never put API keys or passwords into either document or the repository.

## NEWSRUN shortcut

When the user sends `NEWSRUN` as an instruction (case-insensitive), prepare and publish a complete DNU edition. Use the last 24 hours ending at the time of the run in Europe/Vienna unless the user states another coverage window. Follow the editorial policy and the latest user instructions. Check every configured source, using feeds and headline listings first, then Firecrawl for promising original article pages; investigate zero-result sources with alternate permitted routes. Reuse the article cache, verify publication dates on article pages, review relevance, summaries, placement, duplicates and source diversity, and keep a source-level audit. Update the prepared edition, run the relevant checks and build, then publish the website. Once the shared Supabase project is active, also run `npm run publish:shared` with server-only Supabase credentials so public visitors see the new edition. Report the coverage window, article and source counts, unresolved sources and any collection or publication blocker. Do not claim a complete run when one did not occur. Merely discussing or defining `NEWSRUN` does not trigger a scrape.

## FEEDRUN shortcut

When the user sends `FEEDRUN` as an instruction (case-insensitive), prepare a fresh DNU edition from the last 24 hours of outlets with a direct publisher feed in `server/feeds.js`. This is a narrower run than `NEWSRUN`: use no Firecrawl, Google News, third-party scraper or crawler service, and do not imply that all configured sources were checked. Request the RSS or Atom feeds directly, shortlist relevant headlines, then request original publisher article pages directly to verify publication time and read the opening text. A feed timestamp alone does not verify a story for the edition. Investigate failed or stale feeds using other direct publisher feeds and record an outcome for every feed outlet. Use `DIRECT_FEED_WINDOW_HOURS=24 DIRECT_FEED_RESULT_PATH=data/feedrun-result.json node scripts/direct-feed-36h.mjs` for the collection audit; if this workspace's network proxy blocks publishers, trigger `.github/workflows/direct-feed-run.yml` by pushing a fresh `data/feedrun-request.json` or use its manual dispatch, then fetch its `feedrun-result-*` branch. Reuse cached original pages where appropriate. Review and select stories under the editorial policy, including short first-paragraph summaries, placement, duplicate control and source diversity. Rebuild the prepared edition for that 24-hour window, cache usable full bodies, run relevant checks, publish GitHub Pages, and publish the shared Supabase edition when server-side credentials are available. If the shared edition cannot be published, state plainly that the public site still shows the prior shared edition and provide the prepared file for editor import. Report the exact coverage window, how many feed outlets and original pages succeeded or failed, the selected-story count, and unresolved publication blockers. Merely defining or discussing `FEEDRUN` does not trigger a collection.
