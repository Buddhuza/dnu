# DNU

## Project instructions

The versioned [editorial policy](public/editorial-policy.md) covers collection, selection, placement and story text. The separate [site specification](public/site-specification.md) covers the interface, design and exports. On GitHub Pages, both are directly available under `/dnu/`, without links in the public site header. Read and update the relevant document alongside code changes; a written rule does not by itself enforce behavior.

## Shared public site and editor login

The shared edition uses Supabase Auth and Postgres while GitHub Pages serves the website. Visitors can browse, switch views, search, download, email and export. Only the signed-in editor can add, import, edit or manage the site. The editor's changes are saved to the shared edition; public browsers load it immediately on opening and poll for changes every 20 seconds. Dark mode remains a personal browser setting. Batch source collection still requires the local server; an offline `NEWSRUN` can publish its completed edition to Supabase.

To activate shared editing for a new Supabase project:

1. Create a Supabase project. In **SQL Editor**, run [supabase/schema.sql](supabase/schema.sql). The SQL creates a public-read edition and body store, and a publishing function restricted to the DNU editor email.
2. In **Authentication → Users**, create the editor account for the authorised email. Set a fresh password there. Do not put any password in `.env`, GitHub, SQL or chat transcripts used as setup files.
3. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` from the project's API settings for the website build. Copy [.env.example](.env.example) to an ignored `.env.production.local` for a local build. The anon/publishable key is allowed in browser code; never use a service-role key in a `VITE_` variable.
4. Build and publish GitHub Pages with those two variables. Open the public website in one browser and log in from another. Import a sheet or edit a story, wait for **Saved for everyone**, then confirm the public browser updates. A first login before any import shows the bundled prepared edition.

For a future offline `NEWSRUN`, set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` only in the collection process, then run `npm run publish:shared` after reviewing `data/prepared-update.json`. This copies the prepared edition and available full bodies to the shared database. The service-role key must never be used in a website build.

Until the Supabase project and build variables are configured, the live GitHub Pages deployment remains on the earlier browser-local version. Do not publish the new read-only frontend without its shared backend: that would hide editor tools without enabling login.

A local news review app for the 173 outlets in `sources.json` (transcribed from the supplied `agencies_updated.txt`). Choose a source, collect its headlines from a publisher feed where available or Firecrawl otherwise, and refine the results with included and excluded phrases. The prepared news stream can be edited and exported as a Word update.

Before the first shared import, the homepage opens with the bundled edition in `data/prepared-update.json`. The previous English-language edition remains in `data/daily-update-2026-10-24.json`, and its scraped article pages remain in the cache. Dated editions remain in `data/`.

For a complete published update, tell Codex `NEWSRUN`. That shortcut runs the last 24 hours in Vienna time unless you specify another window, checks every configured source under the editorial policy, audits omissions and publishes the new edition. Defining or discussing the shortcut does not start a scrape.

For a quick preview that does not clone or install the project, open the [static GitHub Pages preview](https://buddhuza.github.io/dnu/). Once shared login is activated, visitors see the current edition and exports, while the editor can log in to change it. Source-list collection still requires the local server or an offline `NEWSRUN`; the logged-in Pages editor can add individual URLs with a browser Firecrawl key.

## Test an unattended collection

The **Test daily collection** GitHub Actions workflow runs the existing headline-first collection across all configured sources and builds a draft update. It runs only when started manually; it does not change the public site or create a schedule. A run uses Firecrawl credits.

1. In the GitHub repository, add a repository secret named `FIRECRAWL_API_KEY` under **Settings → Secrets and variables → Actions**. A key saved in the website's browser storage is not available to GitHub Actions.
2. Open **Actions → Test daily collection → Run workflow** and select the `main` branch.
3. Open the completed run. Its **Summary** shows the number of sources visited, selected stories, and source failures. Download the `daily-collection-test-…` artifact for the draft `prepared-update.json` and collection review file.

The job fails if the key is missing, a source was not visited, the audit lacks a source, or the draft has no stories. Source-level failures are shown for investigation even when the overall run completes. Running it does not enable automatic publication; that needs a separate scheduled workflow and a publication review gate.

## Manage the website

In local development, use **Manage site** in the top bar to edit the site title, show or hide page areas, rename and reorder sections, edit or hide stories and their summaries, add a story, add or hide news sources, and adjust light and dark palettes, font, and text size. The top bar also has a dark mode switch. Text starts at 18 px. Changes preview immediately and save to the current browser. The website header has no logo; the supplied Word template retains its OSCE logo. **Download** exports only the checked stories, each with the publisher's headline capitalisation preserved unless it is all caps, one factual summary sentence adding information beyond the headline, and the linked agency name, using the supplied Word template and including local edits. Its filename includes the coverage start and end in Vienna time, and the last page ends with the required disclaimer below a rule. The website shows the same disclaimer above its coverage note. Selecting a source on the left opens its website beside the update; publishers that block embedding can be opened with the direct link above the frame.

Press **Edit** beside **Download** in the update header to show a checkbox for every story. Press **Save** to return to the update with only checked stories visible. Reopen **Edit** to change the selection; it is saved in this browser, and Word downloads use the checked stories. In Edit mode, drag a story (or use its handle on a touch screen) to place it before or after another story, or drop it on a section, subsection, country heading, or empty target. Placement and order are saved in this browser and used by the Word download. The magnifying glass beside **Add** searches the visible update; use the arrow buttons or Enter to move between matching stories.

The **Import spreadsheet** button beside **Add** reads a DNU database export or a similar `.xlsx` or `.csv` file in your browser. It previews the number of usable and skipped rows, then replaces only the update displayed in that browser with DNU headlines, short summaries, linked agencies, and section headings. A row whose article URL matches the prepared edition reuses its reviewed DNU wording and placement; other rows use the spreadsheet placement and a factual sentence from the article body where possible. The full Body column is retained in the browser cache for later spreadsheet export, but is not displayed in the DNU. This import uses no Firecrawl credits and does not publish to GitHub Pages. Open Import again to restore the published edition.

The spreadsheet icon between **Email** and **Search** exports the currently visible stories to an `.xlsx` workbook for database import. Columns are Date, Source, Region, Countries, Local Regions, Organizations, Themes, Types, Source URL, Heading, and Body. Region and the first Countries or Organizations entry follow each story's current heading in the update, including moves and Lead stories; other countries and organisations mentioned in the article follow. Optional fields without reliable data are blank. On the local server, full article bodies come from `data/article-cache.jsonl` and its dated shards and missing pages are fetched only when needed. The GitHub Pages deployment includes a public `article-bodies.json` with readable full bodies for the prepared edition. The browser saves retrieved bodies in IndexedDB. For uncached stories it can use the Firecrawl key entered through **Add**, whether remembered in this browser or kept for the current tab. If an article is unavailable, export continues with the others and shows the final counts and failed titles. Non-English articles that yield a verified English headline and summary are marked `(文A)` in the update; their spreadsheet body uses a full English translation when one is available.

To publish the prepared edition with its body cache, run `npm run build:pages:with-cache`, then `node scripts/sync-pages.mjs dist /path/to/gh-pages-worktree` and commit and push that worktree. The sync overwrites current files while retaining older hashed files in `assets/` so an already open browser tab can still load its Add dialog after a deployment. Do not delete the old hashed assets during deployment. The generated `dist/article-bodies.json` is publicly accessible. It contains extracted article text, not Firecrawl credentials or the raw scrape cache. Rebuild it after changing `data/prepared-update.json` or any article-cache shard.

Press **Add** beside those controls to paste up to ten original article URLs, one per line. The importer extracts an English headline and a distinct one-sentence summary, then assigns each story to the report taxonomy. It accepts articles of any age. A publisher timestamp is used when available; otherwise the importer estimates the date and time from the article or URL. If it finds no date, it stamps the time of import. The Add dialog identifies which method was used and shows times in Vienna time (CET or CEST according to the date). Added stories are checked by default, can be unchecked in Edit mode or moved in Manage site → Stories, and are saved in this browser. The server-backed app uses its configured Firecrawl key; the public static page asks for a Firecrawl key in the dialog, sends it directly to Firecrawl over HTTPS and keeps it for the current browser tab unless **Remember key in this browser** is selected. Each imported article requires a Firecrawl scrape. If an imported story falls outside the prepared edition's period, the displayed coverage dates and Word filename expand to include it.

Section headings default to uppercase 26 px text, with larger site and report titles. The report coverage date appears beneath **DAILY NEWS UPDATE** at headline text size. Change heading size, capitalization, width, section names and subsection lists in **Manage site**. The light palette uses a beige background. International Organisations appears under Miscellaneous. Source-list categories only organize outlets for browsing; international agencies can supply articles in any report section. The current lead section has four major Ukraine headlines and one Middle East headline; its topic is labeled **MIDDLE EAST**. Other headlines remain in their regional sections.

The manager's **Save & share** tab exports and imports a JSON settings file. Browser edits are private to that browser. To publish them for all visitors, replace `data/site-config.json` with the exported file, rebuild, and redeploy the site. The public site's default settings come from that file.

## Run locally

Requires Node.js 20 or newer. A Firecrawl API key is needed for sources without a usable feed.

```bash
npm ci
export FIRECRAWL_API_KEY=... # Optional for feed sources; needed for other sites. Never commit it.
npm run dev
```

Open the Vite development server URL shown in the terminal (normally port 5173). The API runs on port 3001. For a built frontend, run `npm run build` then `NODE_ENV=production npm start` and open port 3001.

With `FIRECRAWL_API_KEY` configured, `npm run collect:daily` prepares a rolling 24-hour edition. Each invocation gets its own checkpoint and refreshes headline listings, except listings fetched in the preceding ten minutes. Extracted articles and compressed Firecrawl article pages are kept in `data/article-cache.jsonl` and dated shards such as `data/article-cache-2026-10-24.jsonl`; subsequent scans read all shards and reuse pages without spending article-page credits. New shards start before a file reaches GitHub’s size limit. The active `data/prepared-update.json` is replaced on every run. Previously selected stories whose publication times still fall inside the new window are re-included; expired stories drop out. Earlier editions are archived. Commit the cache files to retain them across machines. Legacy URLs recorded only in `data/auto-scrape-history.jsonl` may require one recovery fetch because that file does not contain article content. Run `npm run build:pages:with-cache` before publishing to GitHub Pages so asset links resolve under `/dnu/` and the full article cache is included.

Run `npm test` for the filtering, feed parsing, Firecrawl request, source verification, and Word report checks. The server requests one source when you press **Collect headlines**. For the publisher feeds listed in `server/feeds.js`, a quick check uses the feed's exact headline, link, and timestamp at zero Firecrawl cost. A complete check opens the matching original article pages with Firecrawl when a key is available and requires a publication time on each article page. If a feed fails or contains no usable timestamped entries, the app falls back to Firecrawl when a key is configured. For Firecrawl sources, **Collect headlines** is a quick three-page check; **Scan all listed articles** continues through every matching article link returned by that listing, ten pages per request. Responses are cached for five minutes. A zero-result scan triggers checks of common feed URLs, another listing page when available, and a Firecrawl site search limited to recent results. Search results are checked on the original article pages before inclusion. Collection now prioritises OSCE and external cooperation, excludes non-English articles, and limits Russian outlets to Russia-focused reporting. The source verification panel distinguishes empty listings, keyword mismatches, page errors, missing dates, and stories outside the coverage window, and suggests a next step for each source. A zero-result scan does not establish that the source had no relevant news, even after a complete scan, because listings, feeds, and search results may omit articles. Firecrawl usage and extraction quality depend on the sites and your plan. Source-list scans do not fabricate missing dates; the Add dialog explicitly labels its inferred or import times.

Use **Verify all sources** in **Manage site → Collect** to visit every configured outlet, including outlets hidden by the current region or search filter. **Verify visible sources** limits the check to the current sidebar filter. Automatic scans use publisher feeds at zero Firecrawl cost where available. Otherwise Firecrawl reads a headline listing and assigns priority from the visible headline and description; the app opens the top-ranked article links three at a time, stopping after two accepted stories or twelve links. Already cached article pages and extracted stories are reused, including after a server restart. **Scan all listed articles** visits every listed candidate, and its manual rescrape option can refresh a cached page. A shortlist can miss relevant stories whose headlines look unpromising. If no story qualifies, scans try an alternate feed, listing, and site search. The daily collection script uses the same 12-link shortlist unless `COLLECTION_DEEP=1` is set. Every source receives an outcome in the collection panel, and unresolved sources keep an explanation and a retry button. Successful alternate listing pages are saved in this browser for the next scan; collection pages for provided sources can also be edited in **Manage site → Sources**. Clicking an outlet on the left opens its website beside the Daily news update. Batch source collection requires the local server; the published GitHub Pages site can import individual pasted URLs through Firecrawl when a key is entered in the Add dialog.
