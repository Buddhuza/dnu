# DNU

A local news review app for the 173 outlets in `sources.json` (transcribed from the supplied `agencies_updated.txt`). Choose a source, collect its headlines from a publisher feed where available or Firecrawl otherwise, and refine the results with included and excluded phrases. The prepared news stream can be edited and exported as a Word update.

The homepage opens with a **Daily news update** covering the 24 hours from 12 October 2026 at 13:39 to 13 October 2026 at 13:39 (Vienna time). It contains 95 selected English-language headlines from 66 listed sources, linked to their original articles. Read them in a single stream or download a Word report. The snapshot in `data/daily-update-2026-10-13.json` records a listing-page attempt for the supplied websites and a review of candidate article pages; it is a selected roundup, not an automatically refreshed or exhaustive archive. Original article pages were sampled for 89 fetched sources with no selected story. Four listing pages could not be fetched. Earlier editions remain in `data/`.

For a quick preview that does not clone or install the project, open the [static GitHub Pages preview](https://buddhuza.github.io/dnu/). It displays the prepared update, supports content management, imports pasted article URLs with a Firecrawl key entered in the Add dialog, and exports a customised Word update. Source-list batch collection requires the full server app below.

## Manage the website

Use **Manage site** in the top bar to edit the site title, show or hide page areas, rename and reorder sections, edit or hide stories and their summaries, add a story, add or hide news sources, and adjust light and dark palettes, font, and text size. The top bar also has a dark mode switch. Text starts at 18 px. Changes preview immediately and save to the current browser. The website header has no logo; the supplied Word template retains its OSCE logo. **Download** exports only the checked stories, each as a sentence-case headline ending in a period, one factual summary sentence adding information beyond the headline, and the linked agency name, using the supplied Word template and including local edits. Its filename includes the coverage start and end in Vienna time, and the last page ends with the required disclaimer below a rule. The website shows the same disclaimer above its coverage note. Selecting a source on the left opens its website beside the update; publishers that block embedding can be opened with the direct link above the frame.

Press **Edit** beside **Download** in the update header to show a checkbox for every story. Press **Save** to return to the update with only checked stories visible. Reopen **Edit** to change the selection; it is saved in this browser, and Word downloads use the checked stories. In Edit mode, drag a story (or use its handle on a touch screen) to place it before or after another story, or drop it on a section, subsection, country heading, or empty target. Placement and order are saved in this browser and used by the Word download. The magnifying glass beside **Add** searches the visible update; use the arrow buttons or Enter to move between matching stories.

Press **Add** beside those controls to paste up to ten original article URLs, one per line. The importer extracts an English headline and a distinct one-sentence summary, then assigns each story to the report taxonomy. It accepts articles of any age. A publisher timestamp is used when available; otherwise the importer estimates the date and time from the article or URL. If it finds no date, it stamps the time of import. The Add dialog identifies which method was used and shows times in Vienna time (CET or CEST according to the date). Added stories are checked by default, can be unchecked in Edit mode or moved in Manage site → Stories, and are saved in this browser. The server-backed app uses its configured Firecrawl key; the public static page asks for a Firecrawl key in the dialog, sends it directly to Firecrawl over HTTPS and keeps it only until the dialog closes. Each imported article requires a Firecrawl scrape. If an imported story falls outside the prepared edition's period, the displayed coverage dates and Word filename expand to include it.

Section headings default to uppercase 26 px text, with larger site and report titles. The report coverage date appears beneath **DAILY NEWS UPDATE** at headline text size. Change heading size, capitalization, width, section names and subsection lists in **Manage site**. The light palette uses a beige background. International Organisations appears under Miscellaneous. Source-list categories only organize outlets for browsing; international agencies can supply articles in any report section. The current lead section has four major Ukraine headlines and one Middle East headline; its topic is labeled **MIDDLE EAST**. Other headlines remain in their regional sections.

The manager's **Save & share** tab exports and imports a JSON settings file. Browser edits are private to that browser. To publish them for all visitors, replace `data/site-config.json` with the exported file, rebuild, and redeploy the site. The public site's default settings come from that file.

## Run locally

Requires Node.js 20 or newer. A Firecrawl API key is needed for sources without a usable feed.

```bash
npm ci
export FIRECRAWL_API_KEY=... # Optional for feed sources; needed for other sites. Never commit it.
npm run dev
```

Open the Vite development server URL shown in the terminal (normally port 5173). The API runs on port 3001. For a built frontend, run `npm run build` then `NODE_ENV=production npm start` and open port 3001.

Run `npm test` for the filtering, feed parsing, Firecrawl request, source verification, and Word report checks. The server requests one source when you press **Collect headlines**. For the publisher feeds listed in `server/feeds.js`, a quick check uses the feed's exact headline, link, and timestamp at zero Firecrawl cost. A complete check opens the matching original article pages with Firecrawl when a key is available and requires a publication time on each article page. If a feed fails or contains no usable timestamped entries, the app falls back to Firecrawl when a key is configured. For Firecrawl sources, **Collect headlines** is a quick three-page check; **Scan all listed articles** continues through every matching article link returned by that listing, ten pages per request. Responses are cached for five minutes. A zero-result scan triggers checks of common feed URLs, another listing page when available, and a Firecrawl site search limited to recent results. Search results are checked on the original article pages before inclusion. Collection now prioritises OSCE and external cooperation, excludes non-English articles, and limits Russian outlets to Russia-focused reporting. The source verification panel distinguishes empty listings, keyword mismatches, page errors, missing dates, and stories outside the coverage window, and suggests a next step for each source. A zero-result scan does not establish that the source had no relevant news, even after a complete scan, because listings, feeds, and search results may omit articles. Firecrawl usage and extraction quality depend on the sites and your plan. Source-list scans do not fabricate missing dates; the Add dialog explicitly labels its inferred or import times.

Use **Verify all sources** in **Manage site → Collect** to run a complete check of every configured outlet, including outlets hidden by the current region or search filter. **Verify visible sources** limits the check to the current sidebar filter. Feed sources are completed first; other websites then use Firecrawl. Requests are paced to respect a ten-per-minute Firecrawl limit; collecting all 173 provided sources can take hours and consume credits for sources without feeds. Every source receives an outcome in the collection panel, and unresolved sources keep an explanation and a retry button. Successful alternate listing pages are saved in this browser for the next scan; collection pages for provided sources can also be edited in **Manage site → Sources**. Clicking an outlet on the left opens its website beside the Daily news update. Batch source collection requires the local server; the published GitHub Pages site can import individual pasted URLs through Firecrawl when a key is entered in the Add dialog.

Internazionale appears under **Miscl**. Its collection uses the public Reuters feed at `https://www.internazionale.it/ultime-notizie-reuters`, accepts only article links from that feed, and labels them “Reuters”. Source collection outcomes remain in the prepared update JSON for audit but are not displayed on the website or in Word. The NewsNow trial found that Firecrawl could read the World News index and follow a redirect to the original publisher, but the index lacked reliable publication times and the tested article was outside the coverage window. Live headline collection is in **Manage site → Collect**. The **Daily news update** stream can be edited in Manage site and exported to Word using the supplied template.

Montsame now uses its English politics listing at `https://montsame.mn/en/more/302`; a live check on 14 October found 30 links, checked three matching article pages, and extracted three dated stories. C-SPAN's listing also returned links in a fresh Firecrawl check, so its previous listing failure was not treated as permanent. Firecrawl currently rejects Meta.mk as an unsupported site and cannot retrieve NikVesti's current listing; their rows should remain unresolved until a working publisher feed or permitted article access is available.

Word exports use a blanked copy of the supplied example in `server/templates/daily-update-template.docx`. Its logo, Calibri styles, blue section headings, A4 margins, and page-number footer are preserved. Lead-story topic bands and Miscellaneous country and organisation labels are pale blue; the seven Miscellaneous topic headings are unshaded. The report includes the prepared title, article paragraphs, and the required disclaimer below a rule. The live source verification appears in **Manage site → Collect** and is omitted from the report.

Keyword and site settings, including custom sources and dark mode, are stored in your browser's local storage. They are not shared between browsers. Export settings from Manage site to move them to another browser.
